# AI Companion
```
Browser --(Supabase JWT)--> AI Worker --> Groq (streamed)  --fails before first word--> Gemini
                               |--> Supabase (service role): quota, encrypted history, safety event
```
- **Where:** `cloudflare/workers/ai`. Provider keys live only in the Worker. The browser never sees them.
- **Privacy:** every message is encrypted with AES-256-GCM using `AI_DATA_KEY` before it reaches the database, so a database leak or an admin with database access can't read conversations. Admins have no AI tools. If you lose `AI_DATA_KEY`, history becomes unreadable (new chats still work). Conversations are deleted after 90 days (`ai_retention_days`), on request, and when an identity is deleted.
- **Disclosed:** messages are sent to Groq (and Google's Gemini if Groq fails). Their own retention terms apply. The app tells people this on the AI home screen and in Privacy.
- **Quota:** 20 messages a day per identity (`ai_free_daily_limit`), 6 per minute, 2000 characters per message, 16 messages of context, 600 tokens per reply. Change them without a redeploy: `insert into private.platform_config (key, value) values ('ai_free_daily_limit', '30') on conflict (key) do update set value = excluded.value;` `ai_enabled = false` switches the feature off. A message is counted before the provider call and refunded if both providers fail. Day boundaries are UTC. When Plus exists, raise the limit per identity in `ai_begin_turn`.
- **Modes:** Talk, Vent, Think, Journal, Perspective, Calm, each a short addition to a fixed system prompt (AI not human, brief, no diagnosis, no methods for harm, don't ask for identifying details).
- **Safety:** a pattern check on each message looks for self-harm, violence toward others, and abuse. On a match the app shows a fixed helplines card (emergency services, findahelpline.com, befrienders.org) alongside a reply written with a caring prompt, and the database records only the kind of event, never the text. This is a safety net, not a guarantee: patterns miss things and the model can misjudge. Review it with someone qualified before launch, and add local helpline numbers for your main countries.
- **Models:** `AI_GROQ_MODEL=llama-3.3-70b-versatile` and `AI_GEMINI_MODEL=gemini-3.5-flash-lite` (both current stable ids when this was built). Model ids change often; check the providers' model lists before deploying and when replies start failing.
- **Tested:** `cloudflare/workers/ai/e2e.mjs` (26 checks) runs the Worker against stand-ins for Supabase, Groq and Gemini: auth, CORS, validation, streaming, ciphertext-only storage, history, context, ownership, fallback, quota, refund, crisis detection, safety log, deletion. Database tests cover quota, burst limit, ownership, retention and identity deletion. The web screens have not been run in a browser, and the real Groq and Gemini APIs have not been called.
- **Not built:** memory across conversations, voice, specialised companions, per-plan limits (arrive with Plus), and AI usage and cost figures in the admin dashboard.

## Deploy
1. Run `0010_ai.sql`. 2. In `cloudflare/workers/ai`: fill `wrangler.toml` vars; `wrangler secret put` for `SUPABASE_SERVICE_KEY`, `GROQ_API_KEY`, `GEMINI_API_KEY`, and `AI_DATA_KEY` (generate with `openssl rand -base64 32`; back it up somewhere safe); `wrangler deploy`. 3. Set a spend limit on both provider accounts as a second safety net. 4. Set `NEXT_PUBLIC_AI_URL` for the web app.
