# Private chats (direct messages)
- **Who can use them:** starting a chat needs Plus; replying doesn't, so nobody is locked out of a conversation someone started with them. Chats start from a post, comment or Whisper ("Message privately"), so nobody needs a username or any profile. Each side sees the other's contextual name for that chat (or `@name`).
- **Privacy, honestly:** messages are encrypted by the DM Worker with AES-256-GCM (`DM_DATA_KEY`) before they reach the database, so a database leak or an admin with database access can't read them. They are **not end-to-end encrypted**: the Worker can decrypt, which is how a reported chat can be shown to moderators. True end-to-end encryption needs per-device keys, key exchange and multi-device key transfer, and is future work. The app and Privacy page say this plainly.
- **Safety:** Report (the Worker sends the last 20 messages with the report, labelled reporter and reported; it also blocks the person), Block, Leave. Reports appear in the admin "Random and private chats" queue marked "Private chat". Limits: 10 new chats a day, 20 messages a minute, 2000 characters. Blocked pairs can't message each other and don't see each other's chats. Banned or restricted identities can't start chats.
- **Retention:** messages are deleted after 90 days (`dm_retention_days`), when both people have left, and when an identity is deleted. Back up `DM_DATA_KEY`; without it stored messages can't be read.
- **Delivery:** the app checks for new messages every 4 seconds while a chat is open and every 8 seconds on the list. There are no push notifications or typing indicators yet.
- **Tested:** SQL suite (Plus gate, free replies, outsiders, blocks, reports reaching the admin queue, leaving, retention, identity deletion) and 17 Worker checks (`cloudflare/workers/dm/e2e.mjs`) against a Supabase stand-in. The screens haven't been run in a browser.
- **Deploy:** run `0013_media_review.sql` and `0014_dm.sql`; in `cloudflare/workers/dm` fill `wrangler.toml`, `wrangler secret put SUPABASE_SERVICE_KEY` and `DM_DATA_KEY`, `wrangler deploy`; set `NEXT_PUBLIC_DM_URL`.
